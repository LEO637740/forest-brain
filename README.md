## 首次安装与启动

安装 Node.js **24.14.0 或更新版本**（需要内置 SQLite）。在本目录打开终端：

```sh
cd frontend
npm ci
cd ..
node start.mjs
```

Windows 也可以在 PowerShell 执行 `./启动前后端联调.ps1`。启动器从系统 PATH 查找 Node，不含个人电脑路径。前端依赖安装需要联网；后端使用 Node 内置模块，无需 npm install。

启动后会准备 200 棵树的四类规则演示样本及行业规则研判，并自动恢复已配置的模型调用。自动分析在启动时立即检查，此后按配置周期（默认每 60 分钟）或重要公开数据源发生新快照时触发；打开页面和读取已有策略不会调用模型。出现前端地址后打开 http://127.0.0.1:4173/ 。默认配置本机 Ollama 的 `qwen2:7b`，也可在 `.env.local` 中配置 DeepSeek 等服务。准备期间请保持终端开启；Ctrl+C 停止本次启动的服务。使用 `--no-automatic` 可只启动手动模式；默认启动不会复用仍在运行的旧规则服务，请先停止旧服务。

单树策略采用分层分流：启动准备会为 200 棵树各自建立角度、树表、生长、健康四类策略槽位。当前条件简单时，树视图标记为“小脑规则可直接给出策略”；出现雨量/湿度、树表发现、健康异常或明显市场变化时，标记为“提交大脑分析”，由配置模型综合多源资料后输出策略包；休割、树围缺失、影像未配准等情况先标记为“需要补充数据”。这个判定只读当前快照，不会在打开页面时自动调用模型。

角度候选现在使用独立的 `demo-angle-multifactor-v1` 计算记录，逐项纳入树种先验、由种植日期推导的树龄、相对湿度、土壤水分、近 7 日降雨、胶乳黏度和干胶含量，并在策略包与页面中展示各因素的角度贡献、来源、输入完整度和实验计划。当前系数是透明的演示先验，状态固定为 `demo_heuristic / evidence_insufficient`；没有配对角度—流胶量—树皮损耗试验和设备回执时，不称为最优角度，也不会自动下发设备。

第四、第五、第六项现在也使用独立的可复核规则：天气窗口按每个预报时段判断，超过 0.5 mm/时段或降雨概率达到 60% 时暂缓；不超过小雨边界且雨史、土壤水分未偏湿时可以作为候选，但仍要求现场复核。连续降雨后放晴时，近 7 日累计雨量、土壤水分和干胶含量会共同决定暂缓或复核，缺失值不会按 0 处理。市场情景同时读取价格趋势、需求指数、天气约束和树体状态，输出需求 band、可作业树数、排除原因、目标频次以及包含 0 次/周的比较表；频次候选不会自动派发。病虫害页面覆盖每棵目标树的 30 日健康记录，给出 0–100 的演示风险排序、趋势、依据记录和预防性维护建议；该指数不是病虫害概率，也不构成诊断或施药指令。以上阈值、模拟行情、需求和巡查记录均需在接入真实传感器、订单与长期巡查数据后重新校准。

后端健康地址为 http://127.0.0.1:4188/health 。启动器校验版本、接口能力、200 棵树清单及前端跨域权限；旧服务占端口会明确报错，不会误用。

自定义端口（准备脚本、前端和后端会统一）：

```sh
node start.mjs --backend-port 4288 --frontend-port 4273
```

PowerShell 对应：`./启动前后端联调.ps1 -BackendPort 4288 -FrontendPort 4273`。如果另设 HARNESS_URL 或 VITE_HARNESS_URL，必须与 HARNESS_PORT 一致，否则启动失败并提示冲突。

离线演示：`node start.mjs --offline`。依赖需事先安装；此模式不采集公网数据，来源会明确标为模拟或不可用。

只演示规则、保留公开采集：`node start.mjs --rules`。PowerShell 可分别使用 `-Offline` 或 `-Rules`。

强制登录：`node start.mjs --require-login`（可与 `--demo` 等组合）。默认情况下，后端只对带身份的请求检查园区和权限，不带身份的请求可以读写全部数据；加上这个选项后，除健康检查和登录接口外，所有业务请求都必须先选择身份。启动器的就绪检查和每 45 分钟一次的策略准备会自动以“海口机器人运营”身份登录，用完即登出；这个身份可以准备策略，但不能销售、审批，也看不到其他园区。如需更换，可设置 `HARNESS_SERVICE_ACCOUNT`。已在运行的后端如果没有开启强制登录，`--require-login` 会拒绝复用它。单独启动后端可用 `node backend/start-mh.mjs --require-login`；`HARNESS_DB_PATH` 可以指定另一个数据库文件，例如用副本试运行。

自动分析默认启用。当前任务范围扩展为 200 棵树的四类树级能力（角度、树表、生长、健康）以及行业研判；角度按单树排队，其他树级能力按每批 10 棵排队，启动后后台逐项生成，页面读取不会重复调用模型。每 60 分钟检查，滚动 24 小时最多 783 项分析、1566 次模型请求，包含修正请求；天气、行情、仓单或病虫害指导等重要公开数据产生新快照时，会提前触发一次检查。全园自动模型分析需要较长时间和较高模型额度，可在 `backend/config/automatic.json` 调整任务范围和次数上限。`node start.mjs --no-automatic`（PowerShell 用 `-NoAutomatic`）关闭自动分析；`--rules` 或 `--offline` 会自动关闭自动分析。

模型服务发生账户、配置或请求拒绝错误时，即使已生成可查看的规则保底建议，自动流程仍会停止后续模型请求。暂时性服务错误按连续失败阈值暂停，期间完成的免费规则任务不会清零故障计数。处理服务问题后，在模型控制区显式“恢复自动分析”；重启不会自动清除故障暂停，恢复也不会重置滚动调用额度。

## 数据与运行边界

- 默认 `mixed_demo`：适用、地点匹配且有效的公开 API 数据优先；现场档案、设备和暂不可得的数据使用明确标注的模拟样本。园区位置未确认时，不把海口参考点预报作为园区实测。
- 可设置 `HARNESS_DATA_MODE=demo` 演示全模拟树级输入；启动器会把同一模式传给前端和准备脚本。独立启动前端时设置匹配的 `VITE_HARNESS_DATA_MODE` 与 `VITE_HARNESS_URL`。
- 默认加载模型配置并由自动调度恢复调用；重启会从保存的输入恢复未完成任务，并在启动时立即检查。手动点击“大模型生成”仍按当前树和能力发起分析，最多两次模型请求（含一次校正），通过结构、引用与业务约束校验后发布。页面显示实际模型名称及生成方式；复杂任务的大脑候选若校验不通过或模型服务不可用，会保留原始审计并用同一输入快照生成明确标注的规则保底策略包，待人工复核。上下文硬缺项仍显示为待补充数据，不编造事实。模型总开关与自动调度开关独立，暂停模型会阻止自动调度发起新的请求。
- 启动及每 45 分钟更新的样本使用演示规则；规则定时准备会保留仍在运行或已经成功的 configured 结果（包括带 fallback 的保守策略包）；已失败的旧绑定允许被同一输入快照的规则包替换，原失败记录仍可在策略记录中追溯。自动模型任务建立对应单树绑定，点树可只读查看排队、成功、缺项、失败、撤回和过期状态；较旧任务不能覆盖较新的分析。过期模型建议需明确重新生成或在已启用自动范围内等待下一轮。
- “行业研判”完整展示行业判断、管理建议、缺项、不确定性和本次来源统计期。打开或重新读取只发 GET；规则初始化读取缓存或生成明确模拟资料，不刷新公网、不调用模型。同数据模式下行业页优先显示最新仍可查看的 configured 成功/保底记录；configured 失败记录留在策略记录中追溯，规则定时准备可生成当前可复核的规则结果。
- 单树概览展示当前档案测量时间、来源和资料截至时间；一树一策显示本轮冻结输入时间/版本，生长曲线使用该轮输入中的测量。海南、西双版纳的胶乳曲线根据各自园区的固定生产样本，按树位生成可复现的单树示例，尚未接入本树实测采胶数据；西安为试验站，不提供产胶序列。
- “机器人管理”展示海南 A–D 区的浏览器轨道机群，以及预置任务中的模拟机器人；每个设备条目显示负责区域、当前目标、排队及对应任务。模拟任务的进度直接来自任务记录，未加载轨道机群也可查看；轨道机群仍可加载胶园后定位分区，模拟状态不等于真实设备在线状态。
- 数据中心“生产分析”按四个主题集中显示内容，切换主题保留林班、日期范围与所选日期；日度导出及单树明细沿用当前筛选。“收胶点与加工厂”在海南、西双版纳分别提供 2 个收胶点、1 个加工厂的虚构样本，图示不含真实坐标，距离不是导航里程。示例报价固定于 2026-10-19，统一为干胶含量 30% 的鲜胶乳、人民币元 / kg，未计运输和检测等费用，不代表实时市场行情或实际收购承诺；西安不设置生产网点与报价。
- 策略中心“市场与生产”顶部直接展示上期所真实 RU 合约行情、注册仓单及官方市场月报，分开标明交易日期、统计期与抓取时间；期货不会代入园区现货收入。经营测算仍使用明确标注的模拟价格、产量、成本和库存。
- 此版本的机器人、核查、任务与经营操作均为模拟，不发送真实设备指令。
- 本机 SQLite、公开源缓存与策略会话在运行时创建，交付压缩包不携带上一台电脑的任务数据库或会话编号。
- 本地任务缓存升级后会先与服务端同步；若提示冲突，以服务端状态为准，需确认后重新操作。
- 任务同步状态常驻右下角，可展开查看全部园区的待确认数量和重新同步。网络恢复后会自动重试；提交结果未知时保留原提交快照，重连和页面重载都可继续核对。服务器未返回对应记录的业务拒绝保留本地内容、停止重复提交，需核对并修正任务；不要将“浏览器更新待确认”当作已提交。
- 若提示本地保存异常，请保留当前页面后处理。浏览器存储不能写入时，新的提交会等待持久化恢复；此提示不代表真实设备连接状态。
- 任务中心按北京时间选择日期，并分别查看“当日计划”“往期未结束”“日期待核”。旧任务不会叠加到当天时间轴，未记录或无效日期不会自动算作今天；历史记录没有丢失，可从对应范围或原计划日期查找。页面默认跟随今天，手动选日后保持该日期，点击“回到今天”恢复跟随。
- 调整排程可以补填或修改日期及起止时间，保存时核对同园区、同设备、同日的全部任务类型，包括割胶与巡检之间的重叠。确定冲突会阻止保存；其他任务缺少日期或时段时明确提示待核对，不宣称设备空闲。时间轴只画完整有效时段，缺少结束时间的记录独立列出。此核对用于任务中心记录与模拟操作，不替代轨道队列、天气窗口或真实设备调度。
- 任务中心选中任务后，在“策略 → 任务 → 回执”区域可“导出核对单”（HTML，可阅读、打印）或“导出原始记录”（JSON）。仅复制点击时当前任务的浏览器记录，不再次请求服务器；版本号不代表已同步。核对单保留策略来源、匹配回执、证据缺项和储运依赖预览，原始拒绝回执也完整留存，时间统一为北京时间。
- 回执核对同时检查任务范围、派发编号、园区、树号、方案版本、角度、采用身份及时间；重复或矛盾记录不计作完整完成。历史完成不因导出时策略过期而失效。模拟流程与现场处理填写记录分别标注，不替代逐树设备回执；缺少明确树木清单时不推导下发对象，缺少称重时不推算公斤或派车。
- 任务核验失败时，先处理连接或策略问题，再点击“重新核验”。若本区已暂停，核验成功后仍需明确“继续本区作业”，实际开割前会再次核验；过期或撤回的采用策略须取消待执行任务并重新确认。暂停中取消当前任务只推进收臂，不会恢复同区队列。

可在 `backend/.env.local` 配置 `LLM_PROVIDER`、`LLM_MODEL`、`LLM_BASE_URL` 和对应服务密钥以使用其他模型；该文件不要放入交付包。默认本地 Ollama 无需云服务密钥。`--rules` 与 `--offline` 不加载模型配置。

## 模拟收胶到运输签收

在任务中心进入“储运联动”，按原任务日期范围找到已结束的割胶任务，核对完成回执后点击“登记收胶”。只有完成状态但没有证据的任务不能登记；已取消任务如有通过核对的部分完成回执，可收取该部分。一个闭合任务登记一个批次，重复提交不重复收胶。批次列表显示当前园区全部日期，调整任务日期不会隐藏待办理批次。

填写示例收胶点、容器数、经办人和说明，再依次办理：称重（如毛重 20 kg、皮重 2 kg，保存后净重 18 kg 鲜胶乳）→质检（样品编号、干胶含量、人工判定）→安排模拟车辆与加工厂→确认发车→登记签收。质检暂扣须追加复检并通过后再安排运输；签收量可与发运量不同，如 17.8 kg 签收会保留 -0.2 kg 差额及说明。各步均为人工模拟输入，不从树数推算重量，也不自动根据干胶含量作商业判级。

雨情暂缓新收胶和发车，解除后仍需在“天气与设备联动”确认恢复；手工暂停单独解除。室内称重、质检和计划可以留存，已经在途的到货事实也可以登记。发车前可取消后续流程并保留原单据，发车后可暂停核实或登记签收。原任务、完成回执和质检历史不被覆盖。可导出批次 JSON，来源任务的核对单与原始记录也包含关联批次单据。
