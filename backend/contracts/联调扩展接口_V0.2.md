# MH 联调扩展接口 V0.2（后端 2.4.0）

本文件补充 MH 前端新增的模拟业务接口。原 Harness 策略包 schemaVersion 仍为 2.1.0；服务发布版本为 2.4.0，两者不是同一个版本号。机器可读接口见同目录 openapi.json。

## 兼容性

`GET /health` 返回 version=2.3.4，保留既有能力并新增 `field-tree-import`，表示现场树木资料导入与查询接口可用；`GET /api/meta` 的 integrationCapabilities 同步声明此能力。完整列表以 `src/integration-version.js` 为准。跨域默认允许本机 4173 与 5173；自定义端口由启动器传给后端。启动器沿用统一的版本与能力检查，拒绝复用 2.3.3 等旧版本或缺少现场树木导入能力的服务，然后才读取任务或准备策略。

## 现场树木与边界资料

`POST /api/field/trees` 输入 `{siteId,sourceName,observedAt,provenanceMode,coordinateSystem,elevationDatum?,records,boundaries?}`。provenanceMode 为 `measured` 或 `simulated`，coordinateSystem 固定为 `WGS84`；sourceName 和 observedAt 标明资料来源与观测时间。records 每项包含 `{treeId,sourceTreeId?,variety,circumferenceCm,heightM,measurementHeightM,latitude?,longitude?,elevationM?}`；当前 treeId 对应所选园区的 T-0001 至 T-0200，sourceTreeId 保存实际树号。品种、树围、树高及测量高度可为 null；经纬度需成对提供，高程可选且由 elevationDatum 说明基准。树围单位 cm，其余高度单位 m。

可选 `boundaries` 为 `{park:Polygon,zones:[{zoneId:"A",polygon:Polygon},…]}`，需包含园区外环和 A、B、C、D 四个不同分区。Polygon 使用 GeoJSON 结构 `{type:"Polygon",coordinates:[[[经度,纬度],…,[首点经度,首点纬度]]]}`，目前支持一个闭合外环，至少三个不同顶点。可用 `records:[]` 单独导入边界，也可随树木资料一并保存；空树木列表且没有边界时拒绝导入。边界沿用本批资料的来源、观测时间和 measured/simulated 标识。

`GET /api/field/trees?siteId=...` 返回 `{siteId,items,importedCount,boundaries?}`；items 是每棵树按观测时间最新的记录，包含原测量字段及 recordId、sourceName、observedAt、importedAt、provenanceMode、coordinateSystem、elevationDatum。未导入时 items 为空，importedCount 是已覆盖树木数。POST 成功返回 HTTP 201，结构同 GET 并增加本批保存树木数量 savedCount；历次记录追加保存，导入较早历史不会覆盖较新观测。

有已保存边界时，`boundaries` 返回该园区最新观测的园区/分区几何，以及 `recordId、siteId、sourceName、observedAt、importedAt、provenanceMode、coordinateSystem`。边界记录按园区隔离并保留导入历史；仅导入树木不会清除边界。空间地图优先读取导入边界替换内置模拟矩形，分别标注边界来源与树位来源；树木仍沿用现有 A–D 业务分组。

导入后当前档案、新生成策略与新市场测算使用同一份测量投影；fieldRecord 保留字段来源，其他未实测字段仍沿用原模拟来源。已导入树木的生长序列仅使用导入的测量记录；旧策略与输入快照保持冻结。导入本身不触发模型调用。

## 园区范围（2026-10-17）

园区使用 `demo-hainan`、`demo-xsbn`、`demo-xian`，兼容已有短名称。以下是业务范围选择，不是用户身份或角色权限。

| 接口 | 范围与兼容规则 |
| --- | --- |
| GET tasks / task-receipts | 可带 `?siteId=xsbn` 筛选；不带参数仍返回全园区任务，供现有统一同步器合并；任务的 `site` 是历史归属依据 |
| GET actions / constraints / reviews / market/latest | 默认海南；带 `siteId` 时只读取该园区。历史无 siteId 的动作、核查和情景只归海南。采用记录先按园区筛选，再取最近 200 条 |
| GET market/{modelId}；GET/POST reviews/{jobId}/… | 显式带 `siteId` 且归属不匹配返回 404，写操作在修改前拒绝；未传时保留按唯一资源编号查询的兼容行为 |
| POST actions / strategy-validity | 可传期望 siteId；与策略不符时，采用返回 409 STRATEGY_CHANGED，核验返回 valid=false、status=site_mismatch。新前端显式传入期望园区；旧调用省略时仍从策略本身确定范围 |
| POST market-plan | 可传 siteId；与情景归属不符返回 409 SITE_MISMATCH。近期任务占树仅在情景所属园区内计算 |
| POST task-receipts | 可选 siteId 必须与 site 一致；任务及回执引用的策略园区也必须一致，否则该项冲突为 TASK_SITE_MISMATCH。仍须检查 HTTP 200 响应中的 conflicts |

天气约束按园区内树号保留最新采用记录，返回顶层 siteId；失效的最新约束仍阻断，不回退较早窗口。核查证据、当前核查任务及 plannedTasks 都按园区读取，不能将其他园区同编号树的补测或安排套用到当前树。

## 任务

`GET /api/simulation/tasks` 返回 `{items: Task[],operationalEvents: OperationalEvent[],logisticsBatches: LatexBatch[]}`，每个任务和收胶批次包含服务端 revision，三个数组沿用同一可选园区范围。

`POST /api/simulation/task-receipts` 输入 `{tasks: Task[]}`。新任务 revision=0 或省略；更新已有任务必须提交最后读取的 revision。服务端验证状态转换、终态、done/count 等约束后递增 revision。

响应 `{accepted, tasks, conflicts, mode:"simulation"}`。tasks 是服务端当前版本；conflicts 中有 taskId、code、message、revision、task。HTTP 200 表示批次处理完成，**不代表每个任务已接受**。客户端应以服务端版本合并同 ID 任务，显示冲突并让用户重新确认；不得盲目重试旧快照。任务完成或取消后不得恢复到待开始，也不得降低已完成数或清除已保存回执。

`GET /api/simulation/task-receipts` 用于读取最新回执。

## 策略采用与执行前检查

`POST /api/simulation/actions` 支持 adopt_angle、surface_review、adopt_weather。requestId 幂等；相同 requestId 不得提交不同内容。采用时校验树、模式、有效期、撤回和单树最新绑定。

`POST /api/simulation/strategy-validity` 输入 `{strategies:[{treeId,strategyId,runId,revision,dataMode}]}`，dataMode 为 demo 或 mixed_demo。响应 `{items:[{...引用,valid,status,reason,dataMode,expiresAt}],checkedAt}`。页面在队列开始或暂停恢复、进入切割前重新核验，不能将核验请求失败解释为策略有效。已开始切割的参数保持冻结。

## 天气约束

`GET /api/simulation/actions` 是最近 200 条审计记录，不能作为有效约束全集。

`GET /api/simulation/constraints?siteId=hainan` 返回 `{siteId,constraints:[...天气采用记录],operationalEvents:[...运行事件],checkedAt}`。记录带 validity，按树保留最新采用，包括已过期或撤回的记录；失效约束必须显示待确认，不可因列表中消失而自动解除等待。窗口 end、策略有效期和撤回分别检查。

天气 morning、rain、参考点预报属于不同演示情景，不能按同 kind 将它们互相自动替换。针对同一树显式采用新窗口后，新选择替代旧约束；单树角度/树表策略则按模式内最新绑定判断换版。

## 降雨与设备故障事件

事件是人工明确登记的模拟运行事实，独立于天气候选及策略采用。`POST /api/simulation/operational-events` 输入 `{requestId,siteId,kind,zone,note}`：kind 为 `rain` 或 `device_fault`；zone 为 A–D 区的 0–3，降雨也可用 null 表示全园；设备故障必须指定区。siteId 必填，note 为 1–1000 字非空说明。相同 requestId 与事实重试返回当前事件，不重新打开已经关闭的事件。

事件记录为 `{id,siteId,kind,zone,status,note,createdAt,resolvedAt?,resolutionNote?,closedAt?,resumeNote?,mode:"simulation"}`，siteId 返回标准园区编号。状态依次为：

- `active`：异常生效，匹配园区/树区的作业暂缓。
- `resolved`：异常已解除，仍等待人工确认恢复条件，继续阻断。
- `closed`：恢复条件已确认，此事件不再阻断；仍按任务原有流程重新核验、人工继续，不自动启动机器人或运输。

`POST /api/simulation/operational-events/{id}/resolve` 与 `POST /api/simulation/operational-events/{id}/resume` 均输入 `{siteId,note}`，返回完整事件。只有 resolved 可以 resume；跨园区返回 404。同一步骤和相同说明可重试，不改写原说明/时间。登记、解除、恢复均不修改任务、已完成数量或原执行回执。

`GET /api/simulation/operational-events?siteId=...` 返回 `{siteId,items,checkedAt}`；省略 siteId 返回全部园区且 siteId 为 null。`GET /api/simulation/tasks` 同时返回 `{items,operationalEvents,logisticsBatches}`，使用同一个可选园区筛选，供既有任务刷新统一同步，不另设事件或储运轮询。

`POST /api/simulation/strategy-validity` 在策略原有核验通过后检查目标树的运行事件。若存在 active 或 resolved 事件，返回 `valid:false,status:"operational_hold",reason,operationalEventIds`。原策略不被撤回，原天气采用仍保留；其他园区和未受影响的区不受牵连。多个异常分别解除与确认恢复，不能以一次雨停覆盖仍存在的设备故障。

## 收胶、称重、质检与运输模拟流程

接口仅登记本地模拟业务事实，统一重量为 **kg 鲜胶乳**。收胶重量由显式称重输入产生，树数不换算重量，干胶含量不自动折算干胶库存。不会连接实际收胶站、地磅、实验室或车辆。纯共享模型 `shared/logistics.ts` 与任务详情复用同一份回执校验和事件判定。

`GET /api/simulation/logistics-batches?siteId=...` 返回 `{siteId,items,checkedAt}`；不传园区时返回全部园区，siteId 为 null。既有 tasks 接口同步返回同一组批次。

`POST /api/simulation/logistics-batches` 输入 `{requestId,siteId,taskId,operator,collectionPointId,containerCount,note}`，登记一次收胶并返回 stage=`collected` 的完整批次。服务端读取当前园区的真实持久化任务，必须是已结束的割胶任务且至少存在一棵可核对的完成记录。部分取消的轨道任务可收取已有有效完成回执对应的树；未完成/取消的树不进入来源快照。纯完成标签、仍在执行的任务、零完成树、西安试验任务不能登记生产收胶。收胶点必须属于当前园区且 kind 为收胶点。一个任务仅有一个批次，原批次取消后也不能重复收胶。

来源 source 冻结 taskId、taskRevision、taskTitle、taskStatus、有效完成树清单/数量、completionKind 与有效完成 receipts；原任务和执行回执均不修改。每个业务记录包含 `{id,at,operator,note}`，history 另记录 action 与 requestId。

后续均调用 `POST /api/simulation/logistics-batches/{batchId}/{action}`。公共输入为 `{requestId,siteId,revision,operator,note}`，note 必填，服务返回递增 revision 的完整批次：

| action | 追加输入 | 结果与前置条件 |
| --- | --- | --- |
| weigh | grossKg, tareKg | collected → weighed；毛重 > 皮重 ≥ 0，服务端计算净重，最多保留三位小数 |
| inspect | sampleId, dryRubberPercent, decision | weighed/quality-held → ready 或 quality-held；干胶含量在 (0,100]，decision=pass/hold 是人工判定；追加复检保留此前样本，不编造阈值 |
| plan | destinationId, vehicleCode, driver, plannedDepartureAt | ready → planned；目的地须为本园区加工厂，运输量取原净重 |
| dispatch | 无 | planned → in-transit，记录实际模拟发车时间 |
| receive | receivedKg | in-transit → received；记录实收量和 differenceKg=实收−原净重，说明中记录差额情况 |
| pause | 无 | 独立记录 manualHold，不重写当前业务阶段 |
| resume | 无 | 只解除 manualHold，历史暂停记录保留；不会解除雨情 |
| cancel | 无 | 仅发车前可取消，重量、质检和计划记录保留；在途或已签收不可取消 |

雨情按来源中实际完成的树区匹配，active 和 resolved 均阻止新收胶与发车；室内称重、质检、未执行运输计划可继续登记，已在途的到货事实仍可登记。割胶设备故障不否定已经完成的割胶及胶乳。手工暂停与天气独立，手工恢复不绕过雨情发车限制；暂停期间业务步骤须先手工恢复。

每次写入在一个同步 SQLite 事务内完成园区、请求幂等、revision、阶段和事件检查，再原子更新批次与请求记录。相同 requestId 和原始事实重试返回当前批次，即使其已进入后续阶段；同一 requestId 改内容返回 `409 LOGISTICS_REQUEST_CONFLICT`。过时 revision 返回 `409 LOGISTICS_REVISION_CONFLICT`；错误阶段或暂停返回 `409 LOGISTICS_STATE_CONFLICT`；来源证据或雨情阻止收胶返回 `409 LOGISTICS_SOURCE_INVALID`。跨园区资源/任务返回 404。received/cancelled 是终态，禁止改写或重新打开。

## 核查与重算

`GET/POST /api/simulation/reviews`：读取/创建模拟核查；`POST /{jobId}/collect`：模拟采集；`POST /{jobId}/complete`：提交说明及结论；`POST /{jobId}/regenerate`：重算；`GET /{jobId}/events`：审计。

`POST /api/simulation/reviews/refresh` 输入 `{treeId}`。补测/补拍投影共用于 demo 和 mixed_demo；每次返回两个模式各四种能力共八个 runId，并标 dataMode。证据仍标模拟，不因进入混合模式变成实测。一次树围补测不能补造生长历史。

## 其他已有扩展

`POST /api/simulation/market` 计算并保存模拟情景；`GET /api/simulation/market/latest` 查询最近情景；`GET /api/simulation/market/{modelId}` 查询指定情景；`POST /api/simulation/market-plan` 建立模拟任务。

`GET /api/demo/analytics?site=hainan|xsbn&days=7..90` 返回带日期及来源说明的后端模拟序列，不是园区实测产量。


## 二阶段：身份与权限、全园割胶策略、小脑参数与分层记忆（2.4.0）

新增能力：`role-identity`、`park-tapping-plan`、`cerebellum-tuning`、`layered-memory`。启动器会拒绝复用 2.3.x 旧后端。

### 演示身份与服务端权限

- `GET /api/auth/accounts`：演示身份列表（胶农、农场管理、机器人运营、中心管理），含可见园区、承包地块（胶农 1 亩 33 棵）和权限清单。
- `POST /api/auth/login {accountId}` → `{token,expiresAt,account}`；`POST /api/auth/logout`；`GET /api/auth/me`。
- 之后的请求带请求头 `X-Rubber-Session: <token>`。带身份的请求由服务端检查：园区范围（`FORBIDDEN_SITE`）、胶农地块范围（`FORBIDDEN_TREE`）、写操作权限（`FORBIDDEN`）；列表接口按身份过滤；无效或过期身份返回 401。
- 未带身份的请求保持原行为，供 Blender 预览、验收脚本等本机工具使用；设置 `HARNESS_REQUIRE_IDENTITY=true` 后，除健康检查、元数据和登录外的业务接口都必须带身份。
- 演示身份不需要密码；正式部署需接入单位统一登录。

| 角色 | 可见范围 | 主要写权限 |
| --- | --- | --- |
| 胶农 | 本人承包地块（33 棵）及涉及该地块的任务 | 个人记忆 |
| 农场管理 | 所属园区全部数据 | 任务、事件、储运、销售、经营测算、策略采用、全园割胶策略、小脑参数审批、园区记忆 |
| 机器人运营 | 所属园区 | 任务、事件、策略采用；不含销售与经营 |
| 中心管理 | 全部园区（只读作业） | 小脑参数审批、公共记忆 |

### 今日决策

`GET /api/workspace/brief?siteId=` → `{items:[{id,priority,title,conclusion,reason,sourceRefs,action}],plot?}`。按身份生成：农场管理包括本周全园割胶策略、待审批参数、仓容、异常和待处理任务；胶农包括地块养护、近期作业和“这亩地卖了多少”估算。`GET /api/plot?siteId=` 返回胶农地块明细。

### 全园割胶策略

- `POST /api/park-plan {siteId}`：按胶价走势、需求指数、库存/仓容、7 天可割天数和分区设备/树木状态，输出 `stance`（increase/hold/reduce/pause）、每区每周割次、分区日历、产量与仓容预测、`salesHint`。同一输入得到同一 `id`。
- `GET /api/park-plan/latest?siteId=`：最近一次策略（含采用情况）。
- `GET /api/park-plan/{planId}?siteId=`：按 ID 读取保存的原全园方案，返回 `{plan}`，包含采用状态；不会跳转或替换为最新版。默认园区为海南，方案属于其他园区时返回 `409 SITE_MISMATCH`，方案不存在时返回 `404`。
- `POST /api/park-plan/{id}/adopt {siteId,replace?}`：仅农场管理；生成每区每个割胶日一项“待开始”模拟任务（`sourceParkPlanId`），同区同日已有割胶任务时跳过。本周已有采用中的策略时返回 `409 PLAN_CONFLICT`，`replace:true` 会取消旧策略未开始的任务。策略 24 小时后需重新生成。

### 小脑参数自我调整

- `GET /api/cerebellum?siteId=`：当前参数版本、默认值、护栏、提案与历史。
- `POST /api/cerebellum/reflect {siteId}`：大脑按园区气候与近 14 天执行反馈生成提案（状态 pending，不生效）。
- `POST /api/cerebellum/proposals/{id}/decision {decision:'approve'|'reject',note?}`：园区管理或中心审批；批准后天气作业窗口规则、独立校验和全园割胶策略的可割天判断都使用新参数。
- `POST /api/cerebellum/rollback {siteId,toVersion}`：`toVersion=0` 回到默认参数。
- 护栏：每个参数有上下限和单次最大调整幅度，超出时提案被拒绝；批准的调整自动写入园区记忆。

### 分层记忆
